# AI 트레이딩

미국 주식 자동매매 시스템. 전략 채점 → 포트폴리오 배분 → 주문 실행 → 리스크 통제까지를
하나의 파이프라인으로 묶고, macOS 네이티브 앱으로 패키징했습니다.

Python · Streamlit · Alpaca · Finnhub WebSocket · yfinance
약 14,900줄 (테스트 1,100줄 포함) · 전략 25종 · 테스트 80개

> **모의투자(페이퍼) 기본.** 실거래는 브로커 키 연동과 명시적 동의 두 가지를 모두
> 통과해야만 켜집니다. 이 저장소는 투자 자문이 아니며, 손실 책임은 사용자에게 있습니다.

---

## 이 프로젝트에서 실제로 어려웠던 것

자동매매의 어려움은 "매수 신호를 어떻게 만드느냐"가 아니었습니다.
**돈을 쓰는 코드가 24시간 혼자 돌아갈 때 생기는 문제들**이었습니다.
아래 세 가지는 전부 운영 중에 실제로 겪은 사고이고, 그 대응이 이 시스템 설계의 뼈대가 됐습니다.

### 1. 좀비 프로세스가 만든 과잉매매

몇 분 간격으로 같은 종목을 사고파는 일이 반복됐습니다. 전략 버그를 의심했지만 원인은 다른 데
있었습니다. 창을 닫아도 죽지 않은 예전 앱 프로세스가 **다른 전략 설정을 들고 계속 살아 있었고**,
백그라운드 데몬과 같은 장부를 공유하면서 서로가 산 종목을 서로 팔고 있었습니다.
자동매매 토글을 꺼도 그 좀비는 자기 설정대로 계속 거래했습니다.

주기를 늘리거나 조건을 조이는 건 증상 치료였습니다. 근본 원인은 **주문을 낼 수 있는 주체가
4개**(앱 내 루프 · 데몬 · 스케줄러 · 수동/텔레그램)라는 구조 자체였습니다. 그래서 구조를 바꿨습니다.

- 자동매매 실행 주체를 **백그라운드 데몬 하나**로 통합 (앱은 관제만)
- 별도 스케줄러 프로세스를 없애고 데몬의 실행 모드로 흡수
- 모든 주문 경로를 `core/execution.py` **단일 함수**로 합류
- 데몬·앱 양쪽에 단일 인스턴스 가드와 PID 자가복구, 앱 시작 시 좀비 프로세스 정리

### 2. 가격은 그대로인데 매매만 반복

구조를 고친 뒤에도 낭비 거래가 남았습니다. 판 가격과 **거의 같은 가격에 되사는** 패턴이었습니다.
점수가 매수 문턱 근처에서 미세하게 출렁이면 회전 청산 → 재매수가 무한 반복됐습니다.

"며칠 안에는 재매수 금지" 같은 시간 기반 차단은 답이 아니라고 판단했습니다. 정말 급등할 때
못 사게 되니까요. 대신 **가격과 신호 변화를 기준**으로 삼았습니다.

- **재진입 히스테리시스** — 직전 청산가에서 1% 이상 움직이기 전엔 같은 종목을 되사지 않음
- **회전 마진** — 신규 후보가 보유 종목보다 10점 이상 높을 때만 교체
- **리밸런스 밴드** — 목표 비중과 25% 이상 벌어질 때만 조정

시간이 아니라 상태로 막았기 때문에, 가격이 실제로 움직이면 몇 초 만에도 재진입합니다.

### 3. 백그라운드 스레드에서 조용히 멈춘 자동매매

자동매매를 켰는데 아무것도 사지 않았습니다. 로그도 비어 있었습니다. 원인은 Streamlit
백그라운드 스레드에 스크립트 컨텍스트가 붙지 않아 첫 줄에서 예외가 나고, 그게 `except`에
삼켜지고 있었던 것이었습니다.

**조용한 실패가 가장 위험하다**는 걸 여기서 배웠습니다. 이후로는 예외를 삼키는 자리마다
경로를 남기도록 바꿨습니다. 알림 실패와 잔액 조회 실패를 분리해 서로를 가리지 않게 하고,
데몬이 멈추면 텔레그램으로 즉시 알리는 데드맨 스위치를 넣었습니다.

## 설계

```
앱 (Streamlit) ── 관제 · 설정 · 수동 주문
      │  autotrader_config.json (설정) · autotrader.pid (생존)
      ▼
데몬 (autotrader.py) ── 유일한 자동매매 실행 주체
      │
      ├── core/scoring.py    채점 단일 진입점 (전략 점수 · 가격 · 시장 국면)
      ├── core/cycle.py      사이클 1회: 채점 → 배분 → 리스크 → 실행
      ├── core/guard.py      틱 구동 가드: 체결 스트림 수신 즉시 손절/트레일링
      ├── core/execution.py  모든 주문의 단일 깔때기 (자동·수동·텔레그램)
      └── core/control.py    앱↔데몬 제어 계약 (설정·PID·시작/중지)
                             ↓
                    공유 장부 (원자적 쓰기 + 프로세스 간 락)
```

**핵심 원칙: 돈을 움직이는 코드는 한 곳에만 둔다.**
자동매매든 앱의 수동 주문이든 텔레그램 명령이든, 체결·장부 기록·현금 조정·주문 로그·알림은
전부 `execute_orders` / `execute_manual`을 지납니다. 리팩터링 전에는 이 로직이 네 벌로
복제돼 있었고, 실제로 **데몬이 낸 거래만 주문 내역에 안 남는** 버그가 있었습니다.
합치자 그 클래스의 버그가 구조적으로 불가능해졌습니다.

### 실시간성 — 2단 구조

주기를 짧게 만드는 것과 빠르게 반응하는 것은 다른 문제입니다. 전략 점수는 일봉 지표라
1초마다 다시 계산해도 값이 같지만, 손절은 가격 그 자체가 트리거입니다. 그래서 나눴습니다.

| 계층 | 구동 방식 | 반응 | 담당 |
|---|---|---|---|
| 틱 가드 | WebSocket 체결 푸시 (이벤트) | 1초 미만 | 손절 · 트레일링 스탑 |
| 전략 사이클 | 5초 주기 | 5초 | 채점 · 매수 · 회전 · 리밸런싱 |

가격 소스는 **Finnhub WebSocket → Finnhub REST → yfinance** 3단 폴백입니다. 스트림이
끊기면 폴링이 무중단으로 받치고, 스트림이 살아 있으면 폴링 빈도를 자동으로 낮춰 무료 API
호출 한도를 아낍니다. 무료 플랜의 50종목 한도 안에서 **보유 종목을 항상 우선 구독**합니다 —
가장 빠른 가격이 필요한 건 이미 돈이 들어가 있는 종목이니까요.

## 신경 쓴 것

### 동시성 · 데이터 무결성

거래는 "현금과 포지션을 읽고 → 계산하고 → 쓰는" 시퀀스입니다. 그 사이에 다른 프로세스가
끼어들면 갱신이 통째로 사라집니다(lost update). 개별 쓰기만 원자적으로 만드는 걸로는
부족했습니다.

- **재진입 가능한 프로세스 간 거래 락** — 스레드는 `RLock`, 프로세스는 `fcntl.flock`으로
  직렬화하고 둘을 합쳐 재진입을 허용. `execute_orders → record_buy → adjust`처럼 중첩
  호출해도 데드락이 없습니다.
- **원자적 쓰기** — 임시 파일에 쓰고 `fsync` 후 `os.replace`. 쓰는 도중 죽어도 기존 파일이
  깨지지 않습니다. 읽기 실패 시 `.corrupt`로 백업하고 기본값으로 진행합니다.
- **락 안에서 장부 재로드** — 주문을 결정한 시점과 실행하는 시점 사이에 다른 프로세스가
  거래했을 수 있어, 자금 게이트가 묵은 스냅샷을 보고 과매수하는 TOCTOU를 막았습니다.
- **모의/실거래 장부 완전 분리** — 파일 자체가 다릅니다(`state.json` ↔ `state_paper.json`).
  테스트로 격리를 검증합니다.

### 리스크 통제 (다층 방어)

한 겹이 뚫려도 다음 겹이 막도록 쌓았습니다.

| 계층 | 장치 |
|---|---|
| 포지션 | 손절 −7% · 트레일링 익절 · 최대 보유일(점수별 차등) |
| 포트폴리오 | 최대 5종목 · 종목당 25% 상한 · 섹터당 3종목 상한 |
| 계좌 | 일일 손실 한도 도달 시 신규 매수 전면 차단 (kill switch) |
| 시장 | 약세장(SPY 200일선 −2%) 신규 매수 보류 |
| 거래 | 재진입 쿨다운 · 가격 히스테리시스 · 회전 마진 · 자금 게이팅 |
| 체결 | `client_order_id` 멱등성 · 지정가(marketable limit) · 체결 검증 · 슬리피지 가드 |
| 실거래 | 브로커 연동 + 명시적 동의 이중 게이트 |

트레일링 익절은 하드 익절이 승자를 너무 일찍 자르는 문제 때문에 넣었습니다. 목표 수익률에
도달하면 바로 팔지 않고, 고점 대비 되돌림이 임계를 넘을 때만 청산해 추세를 끝까지 끌고 갑니다.

### 검증

- **테스트 80개, 외부 의존성 없이 실행** (`python3 test_core.py`) — 장부 정합성, 분할 매수/매도,
  트레일링, 킬스위치, 히스테리시스, 틱 가드, 체결 검증, 알림 파싱 등
- **백테스트가 라이브와 같은 코드를 씁니다.** 백테스트용 포트폴리오는 실거래
  `PortfolioManager`를 상속해 디스크 I/O만 인메모리로 대체합니다. 손절·트레일링·회전·섹터
  상한·재진입 필터 판정이 전부 부모 코드 그대로라, **백테스트 수익률과 실제 동작이 갈라지지
  않습니다.** 전략 로직을 두 벌로 유지하는 것이 이 도메인에서 가장 위험한 부채라고 봤습니다.
- 테스트는 임시 경로로 장부를 격리하고, 날짜 의존 로직은 클록 주입으로 재현합니다.

### 운영

- **데드맨 스위치** — 데몬이 종료되면 사유와 함께 텔레그램 알림. 앱은 "켜져 있어야 하는데
  죽은" 상태를 감지해 경고합니다.
- **연속 실패 백오프** — 같은 오류가 매 사이클 반복되며 알림만 쌓이지 않도록 지수 백오프
  (최대 30분), 임계 도달 시 1회만 경보.
- **알림 7채널** — macOS/Windows/Linux 데스크톱, 텔레그램, 슬랙, 카카오, 이메일.
- **텔레그램 양방향 봇** — 조회뿐 아니라 `/buy` `/sell` 주문도 가능하되 2단계 확인과 90초
  만료를 둬 오발주를 막았습니다. 체결은 앱과 동일한 단일 실행기를 지납니다.
- **로그 롤오버** — 무한 증가 방지 (로그 800KB, 주문 내역 2,000건).

## 설치 (macOS)

[**최신 릴리스에서 DMG 다운로드**](https://github.com/dabel11/Trading/releases/latest) → 열어서 `AI 트레이딩.app` 을 응용 프로그램 폴더로 드래그.

API 키 없이 바로 실행됩니다 — yfinance 시세와 모의(페이퍼) 계좌로 동작합니다.
서명되지 않은 앱이라 첫 실행 시 macOS 가 차단하면, 시스템 설정 → 개인정보 보호 및 보안에서
"확인 없이 열기"를 눌러주세요.

소스에서 직접 실행하려면 아래로 진행하세요.

```bash
pip install -r requirements.txt
cp .env.example .env          # 키 입력 (없어도 모의투자·시세 조회는 동작)
```

```bash
streamlit run app.py          # 앱 (관제 UI)
```

```bash
python3 autotrader.py         # 자동매매 데몬 (앱 없이 단독 실행 가능)
```

```bash

```

```bash
python3 engine.py backtest --start 2022-01-01 --end 2024-12-31 --trades
```

가능해집니다(이중 동의 필요).

## 한계와 다음 단계

정직하게 적어 둡니다.

- **제어가 파일 폴링 기반** — 앱이 설정을 파일에 쓰고 데몬이 다음 사이클에 읽습니다. 단순하고
  프로세스가 죽어도 상태가 남는 장점이 있지만, 반영까지 최대 1주기가 걸립니다. 로컬 소켓이나
  명령 큐로 옮기는 게 다음 개선안입니다.
- **주문 로그의 출처 라벨** — 모의 모드에서는 자동/수동 거래가 모두 `paper`로 기록돼 사후에
  구분이 안 됩니다. 모드와 경로를 분리해야 합니다.
- **무료 시세의 한계** — Finnhub 무료 플랜은 50종목까지입니다. 유니버스를 더 키우려면
  유료 피드(Polygon/Alpaca SIP)가 필요합니다.
- **실거래 검증은 제한적** — 대부분의 운영 경험이 모의 계좌 기준입니다. 부분 체결·거부·정정
  같은 실거래 엣지 케이스는 검증이 더 필요합니다.
- **국내 주식 미지원** — 토스 API 연동 슬롯만 만들어 뒀고 정식 출시 대기 중입니다.
